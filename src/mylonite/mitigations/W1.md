**Weakness class: tool-description instruction smuggling (W1).** A tool or
function *description* carried instructions the model obeyed. Treat tool metadata
as untrusted: strip or escape directives in descriptions, restrict descriptions
to a strict character allowlist, and never let schema text alter the agent's
policy. The guarded reference twin validates descriptions against an ASCII
allowlist before exposing them.

Advanced tool-poisoning forms this covers (the boundary sanitizer strips each on
every scan, so re-approval after a swap does not help an attacker):

- **Hidden-instruction blocks** — `<IMPORTANT>…</IMPORTANT>` tags or HTML
  comments (`<!-- … -->`) smuggled into a description (Invariant Labs
  tool-poisoning / line-jumping). Stripped.
- **Bracketed pseudo-authority** — `[SYSTEM OVERRIDE] …`, `[ADMIN: …]`. Stripped.
- **ASCII smuggling** — instructions encoded in invisible Unicode tag characters
  (U+E0000–U+E007F) or confusables that render blank but the model reads.
  Removed by the strict-ASCII pass.
- **Rug-pull** — a description approved once, swapped later. The sanitizer runs
  on every scan, so the swapped smuggle is re-sanitized; pair with a description
  fingerprint/diff check to alert on drift.

Known gap (matches the reference guard): plain-prose cross-tool steering
("tool-shadowing" without a smuggle form) — e.g. a description that, in ordinary
English, tells the model to also call another tool — is not reliably detectable
by sanitization. Defend it with tool-call allowlists and confirmation on
consequential tools (see W3/W4), not description filtering alone.
