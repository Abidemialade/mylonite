
 Usage: mylonite gate [OPTIONS] [TARGET]

 Scan -> generate -> validate -> (optionally) open a gating PR. The full pipeline.

┌─ Arguments ─────────────────────────────────────────────────────────────────────────────────────────────────────────┐
│   target      [TARGET]  Target ID: 'reference:vulnerable' / 'reference:guarded', a bundled                          │
│                         'mcp:<family>[:<scope>]', or 'mcp:custom'. Omit when using --target-file. Non-reference     │
│                         targets require --authorize.                                                                │
└─────────────────────────────────────────────────────────────────────────────────────────────────────────────────────┘
┌─ Options ───────────────────────────────────────────────────────────────────────────────────────────────────────────┐
│ --target-file                                    PATH     Path to a custom-target YAML (declares                    │
│                                                           command/args/weakness_classes/seed_arm).                  │
│ --config                                         PATH     A declarative mylonite.yaml run config (target_file /     │
│                                                           authorize / provider / model / budget) — the same one     │
│                                                           `scan` reads. Auto-discovered from ./mylonite.yaml when   │
│                                                           present; an explicit flag always wins.                    │
│ --authorize                                      TEXT     Must equal the target's scope, or its family when it      │
│                                                           declares no scope. Asserts you own the target; see        │
│                                                           SECURITY.md.                                              │
│ --purpose                                        TEXT     One-line description of what the app is for; tailors the  │
│                                                           probes to the app's domain. Overrides 'purpose' in the    │
│                                                           target file.                                              │
│ --open-pr                                                 Push a branch and open the gating PR via gh (opt-in).     │
│ --model                                          TEXT     Model identifier passed to LiteLLM.                       │
│ --planner-model                                  TEXT     Override the model that DRIVES the agent-under-test (the  │
│                                                           planner). Defaults to --model. Same three-role split as   │
│                                                           `scan` — see its --planner-model help for the rationale.  │
│ --customiser-model                               TEXT     Override the model that CRAFTS/REFINES attack payloads    │
│                                                           (the red-team / attacker side). Defaults to --model.      │
│ --judge-model                                    TEXT     Override the model that JUDGES whether an attack landed.  │
│                                                           Defaults to --model.                                      │
│ --out                                            PATH     Output directory for gate artefacts (default: the         │
│                                                           resolved layout's gate dir, normally .mylonite/gate — see │
│                                                           mylonite.yaml `root:` / MYLONITE_ROOT).                   │
│ --max-llm-calls                                  INTEGER  LLM call budget for the scan phase. Not a hard ceiling:   │
│                                                           each seed keeps a small floor, so the worst case is       │
│                                                           higher (see docs/ci-gating.md).                           │
│                                                           [default: (50)]                                           │
│ --runs-on                                        TEXT     GitHub runner label for the scaffolded workflows; use a   │
│                                                           self-hosted label for in-perimeter MCP backends.          │
│                                                           [default: ubuntu-latest]                                  │
│ --workflows              --no-workflows                   Scaffold .github/workflows/ gate + discovery templates    │
│                                                           into the repository. Off by default — this writes files   │
│                                                           you did not ask for.                                      │
│                                                           [default: no-workflows]                                   │
│ --llm-enrich                                              Append a labelled, unverified LLM fix suggestion to the   │
│                                                           PR body.                                                  │
│ --fast                                                    Skip the differential leg for a custom target (no         │
│                                                           boundary-guarded twin). Faster/cheaper but a WEAKER       │
│                                                           guarantee — the kept test no longer proves the safeguard, │
│                                                           not the model, carries the security.                      │
│ --prove-input-control                                     For a black-box HTTP (rest) target: run the input         │
│                                                           data-framing ('spotlighting') differential to measure     │
│                                                           whether that input defence is load-bearing. Opt-in;       │
│                                                           otherwise a rest target is gated by stability + effect +  │
│                                                           consensus.                                                │
│ --randomize-exfil        --no-randomize-exfil             Mint a unique exfil destination per run so the finding    │
│                                                           proves the control/target stops exfil to ANY attacker     │
│                                                           destination, not just the demo address (avoids 'teaching  │
│                                                           to the test'). Defaults ON for a live custom target       │
│                                                           (--target-file); the reference target never randomizes.   │
│ --iterations                                     INTEGER  Differential iterations for the validation leg (default   │
│                                                           3). The kept verdict then reflects reproducibility across │
│                                                           runs — the guarded side must resist every run and the     │
│                                                           attack must fire in all but one. Pass 1 for the fastest,  │
│                                                           weakest gate (fire once).                                 │
│                                                           [default: 3]                                              │
│ --help                                                    Show this message and exit.                               │
└─────────────────────────────────────────────────────────────────────────────────────────────────────────────────────┘

 Examples:
 `mylonite gate reference:vulnerable` -- the full pipeline on the reference target.
 `mylonite scan --command python --arg server.py --scaffold app.yaml --scope my-app` -- write the target file first;
 its scope is the --authorize value below.
 `mylonite gate --target-file app.yaml --authorize my-app` -- gate YOUR app (writes the test).
 `mylonite gate --target-file app.yaml --authorize my-app --open-pr` -- also open the gating PR via gh.
