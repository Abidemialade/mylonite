
 Usage: mylonite generate [OPTIONS] [SCAN_PATH]

 Emit a pytest regression test from a confirmed exploit.

 Offline and deterministic — no LLM call. Reads an ``exploit_*.json`` (written
 by ``mylonite scan``), renders a testkit-based pytest file, and writes it next
 to a co-located copy of the exploit plus a ``fixtures/`` placeholder. For a
 CUSTOM target, pass ``--target-file`` so the target YAML is co-located as
 ``target.yaml`` (the live test needs it). With ``--prove-control`` the emitted
 test asserts the control is load-bearing (``assert_control_holds``) rather than
 just that the target resists. Prints what to run next.

┌─ Arguments ─────────────────────────────────────────────────────────────────────────────────────────────────────────┐
│   scan_path      [SCAN_PATH]  An exploit_*.json file OR a scan dir containing one. Omit and pass --latest to use    │
│                               the newest scan under .mylonite/scans/.                                               │
└─────────────────────────────────────────────────────────────────────────────────────────────────────────────────────┘
┌─ Options ───────────────────────────────────────────────────────────────────────────────────────────────────────────┐
│ --latest                     Use the newest scan under the resolved scans dir.                                      │
│ --scans-dir            PATH  The directory `scan --output-dir` wrote to, when using --latest (default: the resolved │
│                              layout's scans dir, normally .mylonite/scans). An INPUT — where --latest searches for  │
│                              a scan to read, not where this command writes; for the emitted test's output dir see   │
│                              --out. Ignored if you pass SCAN_PATH explicitly instead of --latest.                   │
│ --out                  PATH  Output dir for the emitted test (default .mylonite/generated/<slug>/).                 │
│ --target-file          PATH  For a CUSTOM target: the same target YAML you scanned. Co-located next to the emitted  │
│                              test as target.yaml so the live test can re-drive your real app out of the box.        │
│ --prove-control              Emit a control-efficacy test (assert_control_holds) that proves the control blocking   │
│                              this finding is load-bearing — the attack lands without it and is resisted with it —   │
│                              instead of the standard resists/guard test. Custom targets only (needs --target-file); │
│                              a reference or non-controllable finding falls back to the standard test.               │
│ --help                       Show this message and exit.                                                            │
└─────────────────────────────────────────────────────────────────────────────────────────────────────────────────────┘
