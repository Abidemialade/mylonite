    Blockers¶

    DCR-0006 — exploit.target_id interpolated raw into generated test docstrings, no validation or escaping¶

    • Severity: critical (adjudicated: exploitability 2 × impact 3 × exposure 1.0 = 6.0 → high, then bumped one band — CWE-94 is on the CWE Top 25 list)
    • Standard: CWE-94 / A03:2021-Injection
    • Location: src/mylonite/plugins/_reference/reference_pytest_generator.py:306 in ReferencePytestGenerator.emit
    • Reachable from: mylonite generate, mylonite gate (which calls generate internally)

    Failure scenario. This generator already hardens pattern_id (via _SAFE_PATTERN_ID regex) and control/model/provider (via _py_literal) against exactly this bug — the file's own docstring and DCR history name the """-terminates-the-docstring-and-executes attack these mitigations exist to stop. target_id was missed: it lands bare in the emitted test file's triple-quoted docstrings. target_id is built from an operator- or adapter-supplied family/scope string (TargetFile.family is a bare str with only a 3-name reserved-word validator). If it ever contains a """ sequence, the docstring terminates early and the remainder is interpreted as executable Python the moment pytest collects the emitted, committed test file.

    Evidence. 

                target_id=exploit.target_id,

    Proposed fix. Validate target_id against a safe-charset regex the same way pattern_id is validated, or render it via _py_literal/_slugify at every docstring interpolation site (module docstring and per-template function docstring), matching the existing treatment of pattern_id/control.

    DCR-0005 — Raw exception text stored unredacted into ScanAttempt, persisted verbatim to scan_report.json¶

    • Severity: high (adjudicated: exploitability 2 × impact 2 × exposure 1.0 = 4.0)
    • Standard: V7.1.1 / CWE-532
    • Location: src/mylonite/scan/engine.py:522, 806, 844 in ScanEngine._one_pass and sibling call sites
    • Reachable from: mylonite scan, mylonite gate

    Failure scenario. verdict_reason=str(exc) is written with no redaction pass at three call sites (adapter/customiser/judge exception handling). write_artefacts persists this verbatim — the project's own code already acknowledges this exposure class (redacting target.yaml before it lands in the scan dir specifically because "request.headers and env may carry live credentials, and the scan dir is one the operator is told to commit"; trimming the generate-dir's copied report for the same reason) but never closed it at the source for exception text. A REST/MCP target whose adapter raises with credential-bearing exception text (an echoed Authorization header, an env-var value in an MCP subprocess launch failure) gets that text written to disk in a directory the CLI's own next-step guidance tells the operator to commit.

    Evidence. 

                        verdict_reason=str(exc),

    Proposed fix. Route str(exc) through mylonite._redaction.redact() at all three call sites before storing on ScanAttempt, so the persisted artefact is redacted at the source rather than only at console-render time.

    DCR-0001 — gate silently ignores a bundled mcp:<family> target argument when --target-file (or an auto-discovered mylonite.yaml) is also present¶

    • Severity: high (adjudicated: exploitability 2 × impact 2 × exposure 1.0 = 4.0, promoted from medium)
    • Standard: logic (general correctness, no CWE mapping)
    • Location: src/mylonite/cli.py:3482 in gate, with the trigger broadened by cli.py:3433's mylonite.yaml auto-discovery
    • Reachable from: mylonite gate CLI entrypoint

    Failure scenario. if target_file is not None or target == "mcp:custom": short-circuits before target is inspected. Worse than the original report: target_file = target_file or rc.target_file pulls from an auto-discovered mylonite.yaml even with no --target-file flag typed at all — so mylonite gate mcp:filesystem:/scope run in a directory containing a mylonite.yaml with a target_file: entry silently gates the config's target instead, discarding the positional argument with no warning. The reference:* + --target-file collision is rejected loudly a few lines above with an explicit comment; the mcp:* arm has no equivalent guard. The emitted CI gate becomes a false-green for a target that was never actually gated.

    Evidence. 

        if target_file is not None or target == "mcp:custom":

    Proposed fix. Mirror the existing reference:* + --target-file rejection for any non-mcp:custom target string combined with a resolved target_file (whether from the flag or auto-discovery), so the conflict fails fast instead of silently dropping the positional argument.

    Cross-cutting themes¶

    1. reference_pytest_generator.py's injection hardening is incomplete, not absent. DCR-0006 is a missed arm of a mitigation this file already applies rigorously to pattern_id/control/model/provider. Worth a follow-up audit of every .format()/f-string call site in this file for any other unguarded field before the next release touches it again.
    2. The "silently misroutes/misdrops the operator's argument, produces a misleading result instead of a clear error" pattern recurs across two unrelated commands (DCR-0001 in gate, DCR-0002 in testkit's live re-drive) — the exact class of bug the whole 0.7.7→0.7.10 ladder exists to close, just found in new spots this pass. Neither is in T10/T11/T12's own new code (both are pre-existing cli.py/testkit logic the reviewers happened to read while in the neighborhood) — worth flagging to whoever scopes future task lists that a full sweep of cli.py's remaining raw-target/target-file resolution branches would likely surface more instances.
    3. Redaction-at-the-source is inconsistently applied. target.yaml (redact_target_yaml) and the generate-dir's copied scan_report.json (trimmed, T12) both got explicit redaction treatment where the project noticed the exposure; ScanAttempt.verdict_reason (DCR-0005) is the same class of exposure that was missed. A single shared "this field may carry exception text, redact before persist" convention (rather than case-by-case discovery) would close this whole class at once.
